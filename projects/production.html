The problemEl problema

A notebook that works on my machine is not something a team can depend on. This stage adds the engineering around the agent so that a change can't reach users without passing tests and the evaluation set.Un notebook que funciona en mi ordenador no es algo de lo que un equipo pueda depender. Esta etapa añade la ingeniería alrededor del agente para que ningún cambio llegue a los usuarios sin pasar los tests y el conjunto de evaluación.

How it worksCómo funciona

  1. Serve. FastAPI endpoints with async request handling.Servir. Endpoints de FastAPI con gestión asíncrona de peticiones.
  2. Test. pytest for units and integration, plus the evaluation set from project 2 as a regression check.Test. pytest para tests unitarios y de integración, más el conjunto de evaluación del proyecto 2 como prueba de regresión.
  3. Lint. Linting and type checks on every commit.Lint. Linting y comprobación de tipos en cada commit.
  4. Package. A Docker image built in CI.Empaquetar. Una imagen de Docker construida en CI.
  5. Deploy. GitHub Actions deploys only when every earlier step passes.Desplegar. GitHub Actions despliega solo cuando pasan todos los pasos anteriores.

Stack

FastAPI, asyncio, pytest, Docker, GitHub Actions, YAML.

What I'll measureQué voy a medir

  • Test coverage and pipeline run timeCobertura de tests y tiempo de ejecución del pipeline
  • Evaluation score on every release, compared with the previous onePuntuación de evaluación en cada versión, comparada con la anterior
  • API latency under loadLatencia de la API bajo carga
