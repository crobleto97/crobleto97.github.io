Taking the agent to production

The document agent from project 2, packaged the way a team would run it: behind an API, tested, containerised and deployed by a pipeline on every push.

Status PlannedOrder Project 3 of 3Type Personal project

The problem

A notebook that works on my machine is not something a team can depend on. This stage adds the engineering around the agent so that a change can't reach users without passing tests and the evaluation set.

How it works

  1. Serve. FastAPI endpoints with async request handling.
  2. Test. pytest for units and integration, plus the evaluation set from project 2 as a regression check.
  3. Lint. Linting and type checks on every commit.
  4. Package. A Docker image built in CI.
  5. Deploy. GitHub Actions deploys only when every earlier step passes.

Stack

FastAPI, asyncio, pytest, Docker, GitHub Actions, YAML.

What I'll measure

  • Test coverage and pipeline run time
  • Evaluation score on every release, compared with the previous one
  • API latency under load
